# Portable project memory

Help the next session resume accurately with less repeated explanation. Memory is a reviewed written record, not training, hidden reasoning, or proof that an earlier statement was true.

## Establish the boundary first

Identify the active project and its authoritative sources. Ask for an approved private destination before saving if none is established. Do not create memory in a public transfer repository, another project's folder, a personal cloud service, or an unapproved tool.

If persistent files are unavailable, return a compact handoff for the user to review and save. Never claim persistence without a verified write.

## Load selectively

Read the current project summary, relevant decision entries, and only the sources needed for the task. Do not load every previous engagement or raw transcript.

Resolve conflicts in this order of reasoning: current authorized instruction, current source authority, explicit supersession, date and context. A newer casual remark does not automatically override an approved decision. If a conflict remains, preserve it and name the decision needed.

## Separate four kinds of continuity

1. **Current project state:** objective, boundary, confirmed status, important unknowns, next action.
2. **Decision record:** decision, owner, date, evidence, rationale, alternatives, conditions for revisiting.
3. **Working preferences:** explicit preferences for communication and collaboration, with scope.
4. **Reusable learning:** a generalized lesson supported by an observed result, excluding project facts.

Use the [blank templates](references/memory-templates.md). Create only the records the work needs. Do not build an elaborate memory hierarchy for a short task.

## Update by delta

After a meaningful accepted decision, verified outcome, or direct correction:
- Extract what changed, not the entire conversation.
- Label fact, reported belief, hypothesis, recommendation, or decision.
- Keep source, date, owner, and status where material.
- Strengthen, narrow, supersede, retire, or leave an entry unchanged.
- Record a reversal condition for important judgments.
- Remove duplication and resolve contradictions explicitly.
- Propose the change for review unless a standing instruction authorizes that exact local update.

A single correction is not a universal rule. Do not store inferred personality, sensitive personal details, credentials, raw customer data, or confidential quotations as reusable memory. Keep necessary work evidence only in its approved system; use permitted pointers.

## Resume honestly

At a new session, state what the record supports and what needs rechecking. Separate a last-known state from a current verified state. Do not imply access to previous conversations that are not supplied.

## Close and verify

Return the exact record changed, the meaningful delta, evidence still missing, and the next safe step. Read back saved content. In chat-only mode, label the handoff **not persisted**.

These instructions do not configure or disable the host application's automatic memory. Review those controls separately under organizational policy.
